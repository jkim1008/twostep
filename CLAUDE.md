# CLAUDE.md — Two Step

Two Step is an iOS app for managing money as a **household of exactly two people**: shared transactions (Plaid-imported + manual), budgets, savings goals, and recurring bills, with neutral per-partner attribution. The product's real output is the couple's weekly money conversation, started from shared facts.

## Source-of-truth documents (PRIVATE — one level above this repo, never commit them)

- `../PRD.md` — full product requirements. **Read the relevant section before building any feature.** Every feature has acceptance criteria; they define done.
- `../DESIGN.md` — design system. `App/Theme.swift` implements it verbatim; change the doc first, then the code.

## This repo is PUBLIC

- **No secrets, ever.** Plaid/Firebase secrets live in Google Secret Manager (server) or GitHub Actions secrets (CI). `GoogleService-Info.plist` and `Secrets.plist` are gitignored defensively.
- **No personal data** in code, comments, tests, fixtures, or commit messages.
- Do not reference predecessor projects or private documents' contents anywhere in the repo.

## Stack & architecture (PRD §7)

- **iOS 18 minimum, built with the iOS 26 SDK.** Swift 6, SwiftUI only, MVVM with `@Observable` (never `ObservableObject`/`@Published`), `NavigationStack`, async/await — no Combine.
- **Firestore is the single source of truth** — client SDK with offline persistence. **No SwiftData.** Repositories wrap snapshot listeners into `AsyncStream`s feeding `@MainActor @Observable` stores; one write path only.
- **TwoStepCore** (local Swift package) holds everything with correctness risk: `Money`, `MonthKey`/`WeekKey`, budget math, dedup matching, recurrence, PFC mapping, digest building. **Pure Swift — zero Firebase or UIKit imports.** All of it unit-tested with Swift Testing.
- **Money is integer minor units** (`Money.amountMinor: Int`). Never `Double`, never raw `Decimal` in storage. Decimal appears only at display boundaries via `Money.decimalValue`.
- Cloud Functions (TypeScript) own: Plaid token exchange + sync, invites/membership, deletion cascade. **Membership and Plaid tokens are only ever mutated server-side.**

## Project mechanics

- `TwoStep.xcodeproj` is **generated by XcodeGen and gitignored**. Never hand-edit a pbxproj. To change targets/settings: edit `project.yml`, run `xcodegen generate`.
- Build/test commands:
  - `swift test --package-path TwoStepCore` — fast core tests, run these constantly
  - `xcodegen generate` — after any project.yml change or fresh clone
  - `xcodebuild test -project TwoStep.xcodeproj -scheme TwoStep -destination "platform=iOS Simulator,name=<sim>" CODE_SIGNING_ALLOWED=NO` — full build + UI smoke (`xcrun simctl list devices available` to pick a sim)
- **Build after every change; report pass/fail; fix before moving on.**

## Workflow (PRD §8 — the process is a product)

- All changes land via **feature branch → PR → green CI → merge**. No direct pushes to `main` (branch protection enforces it).
- Tests ship with the change, not after: core logic → Swift Testing in TwoStepCore; functions → vitest + emulator; rules → rules-unit-testing; one UI smoke test kept green.
- Conventional, why-focused commit messages.

## Code rules

- No force unwrapping in production code (SwiftLint enforces).
- Nothing sensitive in UserDefaults; Keychain for anything secret-adjacent client-side.
- Dynamic Type everywhere, 44pt minimum tap targets, VoiceOver labels on non-text elements, never color as the sole carrier of meaning.
- `LocalizedStringKey` for user-facing text.
- Attribution is neutral bookkeeping — no partner-vs-partner comparison surfaces, no scorekeeping UI. This is a product invariant (PRD §2.2), not a style preference.
